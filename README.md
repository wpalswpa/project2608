# LoL 경기는 언제 승부가 결정되는가?
### 인게임 시점별 경기 데이터 기반 승패 예측 및 핵심 승리요인 분석 — 4조

경기 시작 **10분 시점의 상황만 보고** 최종 승패를 예측하고, **왜 그렇게 판단했는지**까지 설명하는 서비스.

**서비스** https://p4.sumzip.com · **저장소** https://github.com/wpalswpa/project2608

| | |
|---|---|
| **정확도** | **0.7366 ± 0.0081** (아무렇게나 찍으면 0.5010 → **+23.8%p**) |
| **승패를 가르는 것** | 골드 차이 > 경험치 차이 > 드래곤 — 서로 다른 두 방법이 같은 순위 |
| **언제 틀리나** | 팽팽한 경기 0.615 ↔ 크게 벌어진 경기 0.947 |
| **5분을 더 보면** | +5.25%p — 단, 그 이득은 **팽팽한 경기에만** |

### 프로젝트는 4단계로 진행했습니다

| | 단계 | 하는 일 | 답하는 질문 |
|---|---|---|---|
| **페이즈 1** | 승패 예측과 원인 분석 | 기능 → 모델 → 피처 → 데이터 순서로 만들고 검증 | 10분 정보로 얼마나 맞히나? 무엇이 승패를 가르나? |
| **페이즈 2** | 골드를 빼고 재분석 | 히트맵으로 중복의 중심이 골드임을 확인하고, **골드를 빼고 처음부터 다시 학습** | 골드 의존도가 너무 컸다. 빼면 무엇이 달라지나? |
| **페이즈 3** | 군집화와 데이터 축소 | PCA로 정보가 몇 축인지 재고, 군집 모델 4종 비교, 나이브베이즈 추가 학습 | 0.73이 정말 한계인가? 승패 말고 다른 구조는? |
| **페이즈 4** | 시점 비교 | 추가 데이터로 10분 vs 15분 | 5분을 더 보면 무엇이 달라지나? |

페이즈 1에서 골드가 압도적 1위로 나왔는데, 그 옆에서 킬 계수가 음수로 나왔습니다.
페이즈 2에서 **골드를 빼보니 킬이 +0.508로 살아나고 점수는 0.002밖에 안 떨어졌습니다** — 지표를 바꿔도 10분 안에서는 상한이 같다는 뜻입니다.
페이즈 3에서 그 상한을 다른 각도로 두드려봤습니다 — 차원을 줄여도(PCA), 묶는 모델을 바꿔도(군집 4종), 예측 모델을 바꿔도(나이브베이즈) **0.73은 그대로**였습니다.
상한이 모델이 아니라 정보량이라는 게 확실해졌으니, 페이즈 4에서 **시점 자체를 바꿨습니다.** 네 단계가 이어져 있습니다.

아래 본문도 이 순서대로입니다 — 페이즈 1 → 2 → 3 → 4 → 서비스.

# 무엇을 만들었나

경기 10분 시점의 숫자 13개를 넣으면 세 가지를 돌려줍니다.

1. **이길 확률** — "파란 팀이 이길 확률 73%"
2. **그 이유** — "돈 차이 때문에 유리하고, 그다음은 경험치"
3. **믿어도 되는지** — "지금은 팽팽한 경기라 이 예측은 자주 틀립니다"

### 왜 이걸 만들었나

- **관전의 "왜"가 비어 있습니다.** 중계에 승률이 뜨지만 산출 근거가 비공개라, 시청자는 "지금 63%"를 봐도 왜 유리한지 모릅니다.
- **분석의 접근성 격차.** 프로팀은 전담 분석 인력이 있지만 일반 유저는 없습니다. 공개 데이터와 기본 도구만으로 복기 우선순위를 뽑는 절차를 보이려 했습니다.
- **통제되지 않은 시점 비교.** "초반에 이미 기울었다"는 통념은 많지만, 같은 경기·같은 지표로 시점만 바꿔 비교한 결과는 찾기 어렵습니다.

### 게임을 모르셔도 되는 최소한의 설명

5명씩 두 팀(파랑 vs 빨강)이 상대 본진을 먼저 부수면 이깁니다. 무승부는 없습니다.
경기 중 **골드(돈)·경험치(레벨)·킬·드래곤(버프)** 같은 숫자가 계속 쌓이므로,
10분 시점에는 이미 "중간 성적표"가 존재합니다. 그 성적표만으로 최종 승패를 맞히는 것이 이 프로젝트입니다.

# 페이즈 1 · 승패 예측과 원인 분석

> **묻는 것** — 10분 정보로 얼마나 맞히나? 무엇이 승패를 가르나?
> **답** — 100판 중 74판 적중. 골드 차이가 압도적 1위.

## 1-1. 정한 순서 — 기능 → 모델 → 피처 → 데이터

**이건 "결정한 순서"이지 "작업한 순서"가 아닙니다.** 무엇이 무엇을 제약했는지를 보이려고 이 순서로 적었습니다.
"이유를 반드시 낸다"가 모델을 정했고, 모델이 피처 형태를 정했습니다.

**실제 작업은 CRISP-DM 순서대로 했습니다** — 데이터 이해 → 데이터 준비 → **분할** → 모델링 → 평가.
아래 ④가 그 과정이고, **분할 진단이 그 종착점**입니다. 분할이 끝나야 모델링을 시작할 수 있습니다.

#### ① 기능부터 정했습니다

"승률 + 이유 + 경고" 세 가지를 돌려주기로 먼저 정했습니다.
**"이유"를 반드시 낸다**는 조건이 이후 모든 선택을 결정했습니다 — 특히 모델 선택에서요.

#### ② 모델 — 후보 8개를 같은 조건에서 비교

| 모델 | 교차검증 정확도 | 연습−검증 격차 | 판정 |
|---|---|---|---|
| **로지스틱 회귀** | **0.7280 ± 0.0163** | **+0.0039** | ✅ 채택 |
| 랜덤포레스트 | 0.7248 | +0.2752 (연습 1.0000) | ❌ 통째로 외움 |
| GaussianNB | 0.7238 | +0.0015 | 2위 이하 |
| SVM (RBF) | 0.7223 | +0.0391 | ❌ 기준 초과 |
| 결정트리 · KNN · HistGB | 0.7140~0.7180 | 최대 +0.1387 | ❌ / 하위 |
| 찍기 (기준선) | 0.5009 | — | 비교 출발선 |

모델을 고른 과정을 네 장면으로 나눠 봅니다.

![점수 비교](reports/figures/model_choice_1_scores.png)

**왜 이걸 봤나** — 가장 먼저 물을 것은 "어느 게 제일 잘 맞히나"입니다.
8종을 **똑같은 조건**(5조각 교차검증, 시드 42)에서 돌려 줄을 세웠습니다.

**결과 — 점수로는 못 고릅니다.** 로지스틱이 1위(0.7280)지만 2위와 **0.003 차이**입니다.
위 7개가 사실상 다 비슷합니다. 아래 찍기(0.5009)와 견주면 전부 확실히 낫지만, **자기들끼리는 구별이 안 됩니다.**

**그래서** — 점수 말고 다른 기준이 필요합니다. 다음 장면으로 넘어갑니다.

![연습 vs 검증](reports/figures/model_choice_2_overfit.png)

**왜 이걸 봤나** — 점수가 비슷할 때 갈라야 할 것은 **"배웠나, 외웠나"** 입니다.
연습 문제(학습 데이터) 점수와 처음 보는 문제(검증) 점수를 나란히 놓으면 드러납니다.

**결과 — 랜덤포레스트가 연습 만점(1.0000)인데 검증은 0.725입니다.**
답을 통째로 외운 것입니다. HistGB도 0.8527 → 0.7140으로 크게 떨어집니다.
반면 로지스틱은 0.7319 → 0.7280으로 **거의 안 떨어집니다.**

**그래서** — 외운 모델은 새 경기에서 무너집니다. 이 격차를 기준으로 판정합니다.

![과적합 격차](reports/figures/model_choice_3_gap.png)

**왜 이걸 봤나** — 앞 장면을 **숫자 하나로** 만들어 합격/불합격을 가르기 위해서입니다.
격차 = 연습 − 검증. 이 프로젝트는 **0.03**을 기준으로 잡았습니다.

**결과 — 초록(통과)이 셋뿐입니다.** 랜덤포레스트는 0.2752로 **기준의 9배**입니다.
로지스틱은 0.0039로 통과합니다.

**그래서** — 남은 후보는 로지스틱·GaussianNB·결정트리입니다. 여기서 마지막 기준이 필요합니다.

![최종 판단](reports/figures/model_choice_4_decision.png)

**왜 이걸 봤나** — 점수와 과적합만으로는 아직 하나로 못 좁힙니다.
그래서 ①에서 정한 조건 **"이유를 반드시 낸다"** 를 마지막 기준으로 씁니다.

**결과 — 로지스틱만 세 칸을 다 통과합니다.** 점수 1위, 안 외움, 그리고 **가중치를 읽어 "왜"를 말할 수 있음**.
랜덤포레스트는 어떤 지표가 중요한지는 말해도 **그게 유리한 쪽인지 불리한 쪽인지(+/−)를 못 말합니다.**

**그래서 로지스틱 회귀입니다.** 덧붙여, **성능이 모델 복잡도의 정확히 역순**이었다는 것도 근거가 됩니다.
10분 정보량이 적어서 복잡한 모델은 배울 게 없어 외우기만 한 것입니다.

*(개념이 낯설면 → [STUDY.md](STUDY.md) **6번 과적합 · 7번 교차검증**)*

**튜닝은 하지 않았습니다.** 골드차 1개만 넣어도 0.7313, 2개면 0.7328로 전체와 거의 같습니다.
정보가 두 지표에 몰려 있어 조정해도 짜낼 것이 없습니다. 남은 시간은 해석과 문서에 썼습니다.

#### ③ 피처 — 38개에서 13개로

원본 38개 중 **11개가 중복**이었습니다.

| 중복 유형 | 예 |
|---|---|
| 거울 컬럼 | `redGoldDiff = -blueGoldDiff` (부호만 반대) |
| 상수배 | `blueGoldPerMin = blueTotalGold ÷ 10` |

지표는 절반이 됐는데 정확도는 오히려 올랐습니다(0.7334 → 0.7369). 불필요한 컬럼이 잡음이었다는 뜻입니다.
모든 지표가 **"양수면 파란 팀 우세"** 로 통일되어 해석도 단순해졌습니다.

승패가 반반이라 **정확도를 1순위 지표로 쓰는 것이 정당**합니다. 치우쳐 있었다면 F1을 썼어야 합니다.

**가장 중요한 규칙 — 분할이 먼저입니다.** 어떤 전처리보다 먼저 학습 7,903 / 시험 1,976으로
나누고 시험지를 봉인했습니다. 전처리를 먼저 하면 시험 데이터의 정보가 학습에 새어 들어가
점수가 가짜로 오릅니다(누수). 오류가 나지 않아 모르고 지나가기 가장 쉬운 실수입니다.

**아래 EDA는 전부 학습셋 7,903행만 보고 그렸습니다.** 시험지를 열어보고 그린 그림으로
"이 지표가 중요하더라"라고 말하면, 그건 답을 보고 문제를 푼 것입니다.

각 그림이 **어떤 질문에 답하려고 그린 것인지**부터 적습니다.

#### 확인 1 — 골드가 벌어지면 정말 이기나?

![골드 차이별 승률](reports/figures/eda1_winrate_curve.png)

가로축은 10분 골드 차이, 파란 선은 그 구간의 실제 승률, 회색 막대는 그 구간의 경기 수입니다.

**결과** — 승률이 S자로 매끄럽게 올라갑니다. 골드 5,000 이상 뒤진 경기는 1.7%만 이기고,
5,000 이상 앞선 경기는 99.5% 이깁니다. 가설대로입니다.

**그런데 중요한 건 가운데입니다.** 회색 막대가 가장 높은 구간(±1,000)이 **전체의 33%**인데
그 구간 승률은 **49.5% — 사실상 동전 던지기**입니다.
즉 **데이터가 가장 많이 몰린 곳에서 골드가 아무 말도 못 합니다.**
뒤에 나올 "접전 정확도 0.615"라는 한계가 이미 여기서 예고됩니다.

#### 확인 2 — 어떤 지표가 승패를 잘 가르나?

![효과크기](reports/figures/eda2_effect_size.png)

지표를 **하나씩만** 놓고 승리한 경기와 패배한 경기의 평균이 얼마나 벌어지는지 쟀습니다
(효과크기, Cohen's d). 0.8을 넘으면 "큰 차이"로 봅니다.

**결과** — 상위 4개가 **골드 1.19 · 경험치 1.12 · 킬 1.09 · 레벨 1.01**로 전부 성장 지표입니다.
반대로 **와드 설치는 0.03으로 사실상 0**입니다.

**그래서** — "시야를 많이 밝힌 팀이 이긴다"는 통념이 이 데이터에서는 **성립하지 않습니다.**
빼도 되지만, 통념이 틀렸다는 것 자체가 발표에 쓸 발견이라 해석용으로 남겼습니다.

#### 확인 3 — 지표끼리 겹치지 않나?

![상관 히트맵](reports/figures/eda3_correlation.png)

지표끼리 얼마나 같이 움직이는지 본 표입니다. 붉을수록 함께 움직입니다.

**결과** — 왼쪽 위에 **진한 덩어리 하나**가 보입니다. 킬↔골드 **0.92**, 경험치↔레벨 **0.92**,
골드↔경험치 **0.90** — **성장 지표 6개가 사실상 한 몸**입니다.
반면 와드 2개와 드래곤·전령은 어디와도 안 붙어 있습니다(거의 흰색).

**그래서** — 게임 규칙상 당연합니다. 킬을 해도, 미니언을 잡아도, 타워를 밀어도 **돈이 들어옵니다.**
문제는 이렇게 겹치면 **모델이 골드 하나에만 가중치를 몰아준다**는 것입니다.
**이 그림이 페이즈 2를 부른 원인**입니다.

#### 확인 4 — 튀는 값을 걷어내야 하나?

![이상치](reports/figures/eda4_outliers.png)

13개 지표를 같은 잣대(z-점수)로 세워 놓고 상자그림으로 본 것입니다.

**결과** — 튀는 점은 **와드 설치·제거에 몰려 있고**(z가 5~10까지), 정작 주력 지표인
골드·경험치·킬은 대부분 ±3 안에 있습니다.

**그래서 이상치를 제거하지 않았습니다.** 이유는 두 가지입니다.
와드는 계수가 0에 가까워 튀어도 예측에 영향이 없고,
골드가 크게 튄 경기는 오류가 아니라 **진짜로 한 팀이 압도한 경기**라 지우면 실제 현상을 지우게 됩니다.

#### 확인 5 — 분할이 제대로 됐나 (여기가 데이터 진단의 끝)

분할은 **한 번 잘못되면 이후 모든 점수가 거짓말이 되는데, 잘못돼도 오류가 안 나서 그냥 지나갑니다.**
그래서 네 가지를 명시적으로 확인했습니다.

![분할 진단](reports/figures/split_check.png)

| 확인할 것 | 왜 봐야 하나 | 결과 |
|---|---|---|
| **인덱스 겹침** | 같은 경기가 양쪽에 있으면 이미 본 문제로 시험 보는 셈 | **0건** ✅ |
| **빠진 행** | 합쳐서 원본 9,879와 같아야 함 | **없음** ✅ |
| **층화** | 두 쪽 승패 비율이 달라지면 정확도를 견줄 수 없음 | 학습 0.4991 / 시험 0.4990 — **차이 0.0001** ✅ |
| **같은 경기 재등장** | `gameId`가 중복되면 사실상 겹침 | **0건** ✅ |

가운데 그림이 층화 결과입니다. **전체·학습·시험이 전부 0.499로 같습니다.**
오른쪽은 골드 차이 분포를 두 쪽에 겹쳐 그린 것인데 모양이 포개집니다 —
**시험셋만 유난히 쉽거나 어려운 경기로 채워지지 않았다**는 뜻입니다.

네 가지가 다 통과했으므로 **여기서부터 모델링을 시작해도 됩니다.**
분할 인덱스는 `data/splits/`에 저장해 두어, 누가 다시 돌려도 같은 문제·같은 시험지를 씁니다.

```bash
python src/split_check.py     # 위 네 가지를 다시 확인
```

# 페이즈 2 · 골드를 빼고 다시 분석

> **묻는 것** — 골드 의존도가 너무 컸다. 골드를 빼면 무엇이 달라지나?
> **답** — 점수는 0.002밖에 안 떨어지는데, 음수로 눌려 있던 지표 5개가 전부 양수로 살아났다.

## 2-1. 왜 골드를 빼봤나

페이즈 1의 계수 그림에서 **골드 하나가 +1.23으로 나머지를 다 눌러버렸습니다.**
그리고 그 옆에는 이상한 게 있었습니다. **킬은 승패와 분명히 관련 있는데(상관 +0.48) 가중치가 음수(−0.11)** 입니다.
그대로 발표하면 "킬을 하면 진다"는 잘못된 결론이 나옵니다.

원인을 찾으려고 상관 히트맵부터 그렸습니다.

![상관 분석](reports/figures/phase2_correlation.png)

**왼쪽은 지표끼리 얼마나 겹치는지, 오른쪽은 그 겹침이 계수를 어떻게 망가뜨렸는지**입니다.

왼쪽에서 **상관 0.7 이상인 쌍이 8개**인데, **그중 4개가 골드가 낀 쌍**입니다
(킬↔골드 0.918, 골드↔경험치 0.896, 골드↔레벨 0.834, 골드↔어시스트 0.758).
VIF로 봐도 **골드가 23.4로 1위**입니다(10 이상이면 중복으로 봅니다).

오른쪽이 문제의 증거입니다. 가로축은 "이 지표가 승패와 관련 있나", 세로축은 "모델이 준 가중치"입니다.
정상이라면 오른쪽 위나 왼쪽 아래에 모여야 하는데, **오른쪽 아래에 빨간 점 5개**가 있습니다.
**승패와 분명히 관련 있는데(가로축 오른쪽) 가중치는 음수(세로축 아래)** 인 지표들 —
킬·어시스트·미니언·타워·정글 몹입니다.

즉 **골드가 중복의 중심**이었습니다. 킬을 하면 돈을 받고, 미니언을 잡아도 돈을 받고, 타워를 밀어도 돈을 받습니다.
골드는 그 모두를 한 번에 담고 있는 지표라, 모델이 골드에만 가중치를 몰아주고
같은 이야기를 반복하는 나머지 지표에는 **남은 오차를 떠넘겨 음수로 만든 것**입니다.

그래서 **가장 상관이 높은 골드 자체를 빼고 처음부터 다시 학습**했습니다.

## 2-2. 골드를 빼니 무엇이 달라졌나

![골드 제외 실험](reports/07_phase2_without_gold.png)

**왼쪽은 계수가 어떻게 바뀌었나, 오른쪽은 그 대가로 점수를 얼마나 잃었나**입니다.
왼쪽에서 회색이 골드를 넣었을 때, 파랑이 뺐을 때입니다. **회색이 왼쪽(음수)인데 파랑은 오른쪽(양수)** 인
지표가 5개 — 빨간 글씨로 표시된 것들입니다.

**첫째, 눌려 있던 지표가 살아났습니다.**

| 지표 | 골드 포함 | 골드 제외 |
|---|---|---|
| **킬 차이** | **−0.107** | **+0.508** |
| 미니언 차이 | −0.157 | +0.114 |
| 어시스트 차이 | −0.079 | +0.096 |
| 타워 차이 | −0.064 | +0.114 |
| 정글 몹 차이 | −0.000 | +0.107 |
| (참고) 경험치 차이 | +0.461 | +0.650 |

**음수로 눌려 있던 5개가 전부 양수로 올라왔습니다.** 킬은 −0.107에서 **+0.508**로, 방향이 바뀌면서 크기도 5배가 됐습니다.
정글 몹은 원래 −0.000(사실상 0)이었는데 +0.107이 됐습니다 — 골드에 가려 아예 목소리가 없던 지표입니다.
즉 **킬이 승패와 무관했던 게 아니라, 골드가 킬의 몫까지 가져갔던 것**입니다. 페이즈 1의 음수 계수는 이걸로 설명됩니다.

**둘째, 점수는 거의 안 떨어졌습니다.**

| 구성 | 지표 수 | 교차검증 | 홀드아웃 | 1위 요인 |
|---|---|---|---|---|
| 전체 13개 | 13 | 0.7315 | **0.7394** | GoldDiff +1.23 |
| **골드 제외** | 12 | 0.7214 | **0.7373** | ExpDiff +0.65 · KillsDiff +0.51 |
| 골드+경험치 제외 | 11 | 0.7197 | 0.7328 | KillsDiff +0.79 |
| 성장 지표 전부 제외 | 7 | 0.6409 | 0.6336 | DragonsDiff +0.37 |

가장 강한 지표를 통째로 뺐는데 **홀드아웃이 0.7394 → 0.7373, 0.002 차이**입니다.
**골드가 특별해서 1위였던 게 아니라, 다른 지표들이 이미 같은 정보를 담고 있어서** 골드가 없어도 대신 채워집니다.

**셋째, 어디까지가 진짜 한계인지도 보였습니다.**
골드·경험치·킬·레벨 같은 **성장 지표를 전부 빼면 0.6336으로 확 떨어집니다.**
드래곤·전령·와드만으로는 안 된다는 뜻이고, **"10분 승패는 결국 성장 격차가 가른다"**는 페이즈 1의 결론이 반대 방향에서도 확인됐습니다.

## 2-3. 그럼 PCA가 안 통한 건 골드 탓이었나

페이즈 1에서 PCA + KMeans가 그냥 "블루 우세 / 레드 우세"로 갈렸습니다.
**골드가 워낙 세서 그런 것 아니냐**는 의심이 자연스럽습니다.
그렇다면 **골드를 빼고 같은 절차를 돌리면 다른 구조가 나와야 합니다.** 확인했습니다.

#### PC1을 무엇이 만드나

축을 만드는 얼굴이 바뀌었을 뿐, **"성장 격차 축"이라는 정체는 똑같습니다.**

#### 군집이 여전히 승패를 되비추나

![PCA 군집 비교](reports/figures/phase2_pca_cluster.png)

골드를 빼서 그게 풀렸는지 보려면, **같은 그림을 나란히 놓고 비교**하면 됩니다.

**결과 — 두 그림이 사실상 같습니다.** 골드를 빼도 **여전히 PC1의 0을 기준으로 빨강과 파랑이 좌우로 갈립니다.**
군집이 승패와 일치하는 비율도 **72.6% → 72.3%** 로 거의 그대로입니다.

#### 그래서 무엇을 알게 됐나

**PCA가 안 통한 건 골드 탓이 아니었습니다.**

골드 하나가 문제였다면 빼는 순간 다른 구조가 드러났어야 합니다. 그런데 안 드러났습니다.

## 3-2. 군집화 — 묶는 모델부터 겨루고 채택

![군집 모델 비교](reports/figures/phase3_cluster_models.png)

**왜 이걸 봤나** — 페이즈 1의 경기 유형 4가지는 KMeans로 묶었는데,
**KMeans를 다른 군집 모델과 비교한 적은 없었습니다.** 예측 모델은 8종을 겨루고 뽑았으면서

**결과 — KMeans의 완승입니다.** 실루엣 점수(잘 나뉜 정도)가 유일하게 0.2 위이고,

**그래서 KMeans를 정식 채택합니다.** 근거는 세 가지 — 점수 1위, **중심이 평균값이라
"운영전 = 킬 9회·CS 456" 같은 표로 해석 가능**, 그리고 시드를 바꿔도 유형 배정이
**99.2~99.9% 재현**됩니다. k=4는 실루엣이 2~6 어디서나 비슷해(0.20~0.22) 숫자가
정해주지 못했고, **설명하기 좋아서 고른 값**이라는 한계는 그대로 유지합니다.

## 3-3. 모델 추가 학습 — 나이브베이즈는 왜 탈락했나

![확률 분포 비교](reports/figures/phase3_nb_proba.png)

**왜 이걸 봤나** — 페이즈 1 비교에서 나이브베이즈가 **로지스틱 다음으로 적합**했습니다
(3위 0.7238, 격차 +0.0015로 전혀 안 외움). 후보를 하나 더 제대로 학습해서
로지스틱과 무엇이 다른지 봤습니다.

**결과 — 정확도는 대등한데 확률의 얼굴이 완전히 다릅니다.**

| | 정확도 | AUC | Brier | "95% 이상/5% 이하" 확신 |
|---|---|---|---|---|
| 로지스틱 (채택) | 0.7394 | 0.8150 | **0.1756** | **4.9%** |
| 나이브베이즈 | 0.7313 | 0.8096 | 0.2179 | **63.6%** |

NB는 경기 3판 중 2판에 "95% 이상 확신"을 겁니다 — 팽팽한 접전에도요.

**왜 이런 일이 생기나** — NB는 "지표끼리 서로 독립"이라 가정하고 확률을 **곱해** 나갑니다.
그런데 우리 지표는 상관 0.9로 얽혀 있어서(페이즈 2), 사실상 **같은 증거를 여섯 번 세는 셈**입니다.
같은 증거를 거듭 곱하니 51%짜리 확신이 99%로 부풀어 오릅니다.

**그래서** — 분할을 10번 바꿔도 로지스틱이 **10번 다 이겼고**(평균 +0.009),
우리 서비스는 확률을 화면에 그대로 보여주므로 NB는 서비스 모델로는 탈락입니다.
다만 "누가 이기나"는 비슷하게 맞히므로 **교차 확인용 보조 모델**로는 값어치가 있습니다.

# 페이즈 4 · 시점 비교 (10분 vs 15분)

> **묻는 것** — 5분을 더 보면 무엇이 달라지나?
> **답** — 전체로는 +5.25%p. 단, 그 이득은 팽팽한 경기에만 몰려 있다.

페이즈 2에서 **가장 강한 지표를 빼도 점수가 0.002밖에 안 떨어진다**는 것을 확인했습니다.
지표를 어떻게 조합해도 10분 안에서는 0.73 언저리가 상한이라는 뜻입니다.
그렇다면 남은 방법은 하나뿐입니다 — **10분이라는 시점 자체를 바꿔보는 것.**

프로 경기 데이터로 **시점만** 바꿔 비교했습니다.

**모델은 페이즈 1과 같은 로지스틱 회귀입니다**(StandardScaler → LogisticRegression, 시드 42).
10분용 모델과 15분용 모델을 **따로 학습해서 점수를 나란히 놓는** 방식입니다.

공정하게 재려면 시점 말고는 전부 같아야 하므로 이렇게 묶었습니다.

| 고정한 것 | 어떻게 |
|---|---|
| 같은 경기 | 10분·15분 기록이 **둘 다 있는 경기 10,656판**만 사용 |
| 한 경기 = 한 줄 | 원본은 한 경기가 블루·레드 두 줄이라, 그대로 쓰면 같은 경기가 학습·시험 양쪽에 들어갑니다. 블루 줄만 남겼습니다 |
| 같은 지표 | 두 시점에 똑같이 존재하는 **5개만** (골드·경험치·CS·킬·어시스트) |
| 같은 분할·모델·시드 | 두 시점이 같은 학습/시험 인덱스, 같은 5조각 교차검증, 시드 42 |

지표가 13개가 아니라 5개인 이유는 이 데이터의 드래곤·전령·타워가 **경기 전체 누적값**이라
"10분 시점의 값"이 없기 때문입니다. 넣으면 미래 정보를 미리 보는 셈이라 뺐습니다.

이렇게 시점 외 모든 조건을 묶었기 때문에, 점수 차이를 **"5분을 더 봐서 생긴 차이"** 라고 말할 수 있습니다.
반대로 **이 숫자를 페이즈 1의 0.7394와 비교하면 안 됩니다** — 데이터(프로 vs 다이아)도 지표 수도 다릅니다.
여기서는 10분과 15분끼리만 비교합니다.

![시점 비교](reports/figures/viz_4_timepoint.png)

**왼쪽은 점수가 얼마나 올랐나, 오른쪽은 무엇이 중요해졌나**입니다.

왼쪽 — **0.704 → 0.756, +5.25%p** 올랐습니다. 빨간 점선(찍기 0.523)과 견주면 확실한 상승입니다.
5분을 더 보는 것이 실제로 도움이 된다는 뜻입니다.

오른쪽 — 회색이 10분, 파랑이 15분에 각 지표가 받은 가중치입니다. **골드가 0.91 → 1.18로 더 커지고,
경험치도 0.17 → 0.43으로 커집니다.** 반대로 **CS는 0.20 → 0.10으로 줄어듭니다.**
라인전에서 미니언을 챙기는 단계가 지나고 **격차 자체가 승패를 말하는 단계로 넘어간다**는 뜻입니다.

그런데 전체 평균만 보면 중요한 걸 놓칩니다. 10분 상황별로 쪼개보면 이렇습니다.

![접전 경기](reports/figures/viz_5_close_games.png)

**10분에 어떤 상황이었느냐로 나눠, 5분을 더 봤을 때 얼마나 나아지는지 잰 그림입니다.**

| 10분 상황 | 비중 | 10분 정보 | 15분 정보 | 개선 |
|---|---|---|---|---|
| **팽팽함 (1,000 미만)** | 52.1% | 0.617 | 0.696 | **+7.8%p** |
| 조금 앞섬 | 37.5% | 0.761 | 0.793 | +3.1%p |
| 많이 앞섬 (2,500+) | 10.4% | 0.928 | 0.928 | **±0.0%p** |

**결과 — 이득이 한쪽에만 몰려 있습니다.**
이미 크게 벌어진 경기는 **5분을 더 봐도 0.928 그대로, 변화가 정확히 0입니다.**
반면 팽팽한 경기는 +7.8%p 오릅니다.

**왜 그런가** — 10분에 팽팽했던 경기의 **59%가 그 5분 사이에 한쪽으로 기울기** 때문입니다.
이미 결판난 경기는 더 볼 것이 없고, **아직 안 갈린 경기에서만 새 정보가 생깁니다.**

**그래서 "5분 더 보면 좋다"가 아니라 "팽팽할 때만 5분이 값어치가 있다"** 가 정확한 결론입니다.

**제목의 답** — 경기의 약 10%는 10분에 이미 끝나 있고, 절반쯤 되는 팽팽한 경기는
그 6할이 10~15분에 갈립니다. "초반에 다 기운다"도 "끝까지 모른다"도 둘 다 틀렸습니다.

## 화면의 숫자는 어디서 나오나

```
브라우저 → web/frontend.py (9504) → web/app.py (9524) → lolwin.predict → artifacts/model.joblib
            화면·중계만              예측 API            예측 전담        학습된 모델 (2.2KB)
```

**각 계층이 무엇을 import 하는지**가 곧 "누가 계산하는가"입니다.

| 파일 | import 하는 것 | 하는 일 |
|---|---|---|
| `web/frontend.py` | `flask` · `urllib` | 화면을 내려주고 `/api/*`를 백엔드로 **중계만**. 예측 코드 0줄 |
| `web/app.py` | `flask` · **`from lolwin import predict`** | 입력을 받아 `predict()`에 넘기고 결과를 JSON으로 반환 |
| `lolwin/predict.py` | **`joblib` · `pandas` · `numpy`** | 모델을 불러 확률과 승리요인을 계산 — **계산은 이 파일뿐** |
| `predict.py` (루트) | `from lolwin.predict import …` | 명령행·기존 코드용 호환 진입점. 계산 없음 |

**`web/` 어디에도 `sklearn`·`joblib` import가 없습니다.** 웹은 계산하지 않고 `predict()`를 부를 뿐입니다.
계산이 두 곳에 있으면 화면 확률과 모델 확률이 갈라져도 아무도 모르기 때문입니다.

### model.joblib 안에는 무엇이 들어 있나

```
Pipeline
 ├─ scaler → StandardScaler      평균 13개 · 표준편차 13개
 └─ model  → LogisticRegression  계수 13개 + 절편 −0.0043
```

**딱 이게 전부입니다(2,209 bytes).** 파이프라인을 통째로 저장했기 때문에
예측할 때 **표준화를 빠뜨릴 수가 없습니다.** 스케일러와 회귀식이 한 덩어리로 묶여 있어서입니다.

### 계산이 실제로 무슨 일을 하는지

`predict()`가 하는 계산은 세 줄로 끝납니다.

```python
z    = (입력값 - scaler.mean_) / scaler.scale_   # ① 표준화
로짓  = coef_ @ z + intercept_                    # ② 계수를 곱해 더한다
확률  = 1 / (1 + exp(-로짓))                      # ③ 0~1 로 눌러 담는다
```

같은 입력(골드 +2,000 등)을 **손으로 계산한 값과 sklearn이 낸 값이 소수점 아래까지 같은지** 확인했습니다.

| 방법 | 결과 |
|---|---|
| 손계산 (①②③ 직접) | 0.818255 |
| `model.predict_proba` | 0.818255 |
| **라이브 `p4.sumzip.com`** | **0.8183** |

**셋이 일치합니다.** 화면에 뜨는 숫자가 학습된 모델이 낸 숫자 그대로라는 뜻입니다.
`web/test_parity.py`가 이 검증을 자동으로 돌립니다.

**"골드차가 크면 승리" 같은 사람이 만든 규칙은 한 줄도 없습니다.** 넣는 순간
"데이터가 검증했다"는 말이 거짓이 되기 때문입니다.

### 승리요인은 어떻게 뽑나

화면의 "이유"는 **계수 × 표준화값(z)** 입니다. 그 판에서 각 지표가 로짓을 얼마나 밀었는지를
그대로 분해한 값이라, 확률과 따로 노는 별도 계산이 아닙니다.

다만 이 기여도는 **다른 지표를 통제한 뒤의 몫**이라, 킬은 음수로 나올 수 있습니다
(페이즈 2 참고). 그래서 화면에는 이 설명을 함께 띄웁니다.

**"골드차가 크면 승리" 같은 사람이 만든 규칙은 한 줄도 없습니다.** 넣는 순간
"데이터가 검증했다"는 말이 거짓이 되기 때문입니다.

# 부록 — 관전 포인트 (게임을 몰라도 이것만)

1. **골드(돈) 차이** — 4,200 이상이면 사실상 결정(적중률 95%), 1,000 미만이면 이제 시작(적중률 62%)
2. **경험치(레벨) 차이** — 돈과 별개로 레벨이 앞서면 유리
3. **드래곤** — 팀 전체가 강해지는 버프

**킬은 왜 목록에 없나** — 킬을 많이 했어도 **돈 차이가 안 벌어졌다면 아직 유리한 게 아닙니다.**
킬을 하면 돈을 받기 때문에, 킬의 가치는 이미 돈 차이 안에 들어가 있습니다.
그래서 "킬 몇 개 앞섰나"가 아니라 **"그 싸움이 돈 격차로 이어졌나"** 를 봐야 합니다.

**한 줄 요약 — 골드차 4천이면 끝난 경기, 1천 미만이면 이제 시작입니다. 킬은 돈으로 바뀌었을 때만 의미가 있습니다.**
