## 지킨 규칙

- **예측은 전부 학습된 모델이 한다.** "돈 차이 크면 승리" 같은 규칙을 사람이 써넣지 않는다.
  넣는 순간 "데이터가 검증했다"는 말이 거짓이 되기 때문이다.
- **시험지 봉인.** 데이터를 연습용 7,903판 / 시험용 1,976판으로 먼저 나누고,
  시험용은 마지막 채점 때 딱 한 번만 열었다. 미리 보면 점수가 가짜로 오른다.
- **화면은 보여주기만.** 웹은 예측 파일(predict.py)을 그대로 불러 쓴다.
  계산이 한 곳에만 있어서 화면 숫자와 모델 숫자가 어긋날 수 없고, 자동 대조 테스트도 있다.
- **저장한 모델은 복원 검증.** 파일로 저장한 모델을 다시 불러왔을 때
  똑같은 답이 나오는지 자동으로 확인한다.

## 무엇으로 만들었나

Python 3.11 · pandas · scikit-learn(Pipeline) · joblib · matplotlib · Flask · pymysql — 전부 버전 고정(`requirements.txt`).
분석은 Windows 네이티브 · 1코어(`n_jobs=1`) · Docker 미사용. 서비스는 팀 서버(맥)에서 `venv311`.

| 부분 | 도구 | 왜 |
|---|---|---|
| 학습·예측 | Python + scikit-learn | 수업에서 배운 범위 |
| 모델 | 로지스틱 회귀 | 점수 1등 + 이유를 숫자로 설명 가능 |
| 데이터 보관 | 팀 MariaDB — SQL 뷰 4종(`v_diff13` `v_clean27` `v_gold2` `v_cluster5`) | 피처 계산식이 **DB 뷰 한 곳**에만 있어 누가 읽어도 같은 13개가 나온다. CSV 폴백은 같은 계산식 |
| 웹 서비스 | Flask 2개 — 백엔드 API(**9524**) + 프런트/프록시(**9504**) | 아래 참고 — 계획에서 바뀐 것. 공개 주소 **https://p4.sumzip.com** → 프런트 |
| 운영 | `check_project.sh` (start/stop/restart/status/logs/test) · `venv311`(Python 3.11) | 팀 서버에서 한 명령으로 켜고 끄고 검증 |
| 모델 저장 | joblib 파일 하나 | 전처리까지 통째로, 복원 검증 |

**계획에서 바뀐 것 — 화면을 Vue/Express 대신 Flask로 (2026-08-31 결정).**
원래 계획은 예측 계산이 파이썬과 자바스크립트 두 군데에 생기는 구조였다.
그러면 화면 확률과 모델 확률이 달라져도 아무도 모른다. 이게 이 설계의 최대 위험이었다.
Flask는 화면도 파이썬이라 `predict.py`를 그대로 불러 쓴다. 계산이 한 곳뿐이라 어긋날 수 없다.
프런트(9504)와 백엔드(9524)를 나눈 것은 DDBM 포트 배정 때문이고, 프런트는 `/api`를 중계만 한다 — 예측 로직 0줄.

## 어기면 안 되는 원칙 7가지 (헌법)

1. **나누는 게 먼저** — 시험지를 봉인한 뒤에 전처리한다. 시험지로 모델·피처를 고르지 않는다
2. **전처리는 Pipeline 안** — 검증 중에도 시험 정보가 안 새게
3. **찍기 점수를 먼저 잰다** — 그래야 "잘했다"를 말할 수 있다
4. **예측은 모델만** — 규칙 하드코딩·확률 수동 보정·외부 승률 API 금지
5. **예측 로직은 `predict.py` 한 곳** — 웹도 노트북도 이 파일을 부른다
6. **재현성 규약 8항목** — 시드 42 · 분할 파일 저장 · 절대경로 금지 · 버전 고정 · 순차 실행 · Pipeline 전처리 · `runs.csv` 기록 · **행 정렬 고정(`gameId`)**
7. **실험 A(다이아)와 B(프로)의 절대 수치를 비교하지 않는다** — 시점 비교는 B 안에서만

> 8번째 규약은 9/1에 추가됐다. 시드가 같아도 **행 순서가 다르면 분할이 달라진다**는 걸
> 재실행 중 발견했기 때문이다(DB는 정렬해 읽고 CSV는 안 해서 점수가 어긋났다). 자세한 건 research.md.

## 최종 성적표

| 항목 | 값 |
|---|---|
| 정확도 (봉인 시험지 1,976판, 시드 42) | **0.7394** — 찍기 0.5010 대비 **+23.8%p** |
| 교차검증 (5조각) | 0.7315 ± 0.0153 · 연습−검증 격차 +0.0022 |
| 10번 다시 재본 범위 | **0.7366 ± 0.0081** (0.7277 ~ 0.7520) · 10번 모두 0.70 통과 |
| F1 / AUC / Brier | 0.7352 / 0.8150 / 0.1756 |
| 승리 요인 | 돈 차이 > 경험치 차이 > 드래곤 (두 방법 일치, 10번 반복에서도 동일) |
| 언제 틀리나 | 팽팽(<1k, 34%) 0.615 → 우세 0.741 → 크게 우세 0.859 → 사실상 결정(4.2k+, 9%) 0.947 |
| 5분 더 보면 (실험 B) | +5.25%p (반복 +4.77 ± 0.89) — 팽팽한 경기 +7.8%p, 벌어진 경기 ±0 |

> 발표에서는 단일 분할 값(0.7394)보다 **반복 평균 0.7366 ± 0.0081**을 대표값으로 말한다.
> 팀 서버 DB의 고정 분할(`ml_split`)로 다시 재면 홀드아웃 0.7136(CV 0.7369±0.014) — 분할이 다르면 값이 다르니 인용할 때 어느 분할인지 적는다.
