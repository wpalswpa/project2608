## Overview

001 명세가 정의한 분석 프로젝트 중 **실제로 동작하는 시스템으로 구현할 부분만** 추려낸 기능 명세다.
경기 스냅샷 하나를 입력받아 ① 승리 확률, ② 그 판단의 근거가 된 지표 순위, ③ 그 예측을 믿어도 되는지에 대한 경고를
한 번의 호출로 함께 반환하는 지도학습 이진분류 서비스를 만든다.
모델은 사전 실측으로 이미 확정되어 있으므로, 이 명세의 초점은 성능 탐색이 아니라 **재현·설명·경고의 구현**이다.
**관측 시점은 10분으로 확정**한다. 15분과의 비교는 시점 인자 구조만 남겨 두고 후속 과제로 이관한다(A4).

**구현 스택은 B — Python 학습 + Vue 3/Express 서비스다(A11).** 다만 순서는 **모델 우선**이다.
학습·예측의 단일 진실은 Python 쪽 `predict.py` 이며, 웹 계층은 그 결과를 **보여주기만** 한다.
두 계층이 같은 답을 내는지는 **서빙 파리티 검증(FR-019)** 으로 기계적으로 강제한다.

## Problem Statement

001 명세는 4일짜리 분석 프로젝트 전체(데이터 검증·모델 비교·시점 비교·문서 산출물·정성 평가)를 다루고 있어
"무엇을 코드로 만들어야 하는가"의 경계가 불분명하다. 18개 기능 요구사항 중 일부는 시스템 기능이고,
일부는 일회성 분석이며, 일부는 미확보 데이터에 묶여 있다. 이 경계를 확정하지 않으면
구현 단계에서 분석 스크립트와 서비스 코드가 뒤섞인다.

웹 계층을 도입하면 여기에 두 번째 위험이 붙는다 — **예측 로직이 Python 과 JavaScript 두 곳에 생기는 것**이다.
그렇게 되면 화면에 뜬 확률과 `predict.py` 가 내는 확률이 갈라져도 아무도 모른다.
이 명세는 그 분기를 **금지(NFR-008)하고 자동 검증(FR-019)** 으로 막는다.

## Target Users

| 사용자 | 이 시스템에 요구하는 것 |
|---|---|
| **일반 사용자·아마추어 팀** | 스냅샷을 넣으면 승률과 "무엇 때문인지"가 함께 나올 것 |
| **중계·해설** | 화면에 띄울 확률과 그 근거를 한 번에 받을 것 |

| **시연 참관자(발표·평가)** | 코드를 읽지 않고 화면 조작만으로 예측·근거·경고를 확인할 것 |

## User Scenarios & Testing

### Primary Scenarios

**S1. 단건 예측** — 사용자가 10분 시점 경기 상태를 입력하면 승리 확률(0~100%)과 예측 결과(승/패)를 받는다.

**S2. 근거 동시 수신** — 예측 결과와 함께, 그 판단에 기여한 상위 지표가 방향(유리/불리)과 크기 순으로 제시된다.

**S3. 신뢰도 경고** — 입력이 학습 범위를 벗어났거나 예측이 취약한 구간(접전)에 해당하면, 결과와 함께 경고가 표시된다.

**S4. 일괄 예측** — 여러 경기 스냅샷을 한 번에 넣어 동일한 형식의 결과 묶음을 받는다.

**S5. 모델 복원 재현** — 제3자가 저장된 모델 파일을 복원해 동일 입력으로 예측하면 저장 이전과 완전히 같은 값을 얻는다.

**S6. 시점 확장** — 15분 스냅샷이 확보되면, 예측 로직을 수정하지 않고 시점 인자만 바꿔 동일 절차로 학습·평가할 수 있다.

**S7. 문서 단독 인수인계** — 처음 접하는 사람이 `README.md` 하나로 문제·실행·구조를 파악하고 예측까지 실행한다.

**S8. 노트북 클린 재실행** — 채점자·검토자가 초기화된 환경에서 최종 노트북을 전량 재실행해 무오류 완주와 수치 일치를 확인한다.

**S9. 사용 적합성 판단** — 모델을 넘겨받은 제3자가 `model_card.md` 만 읽고 자신의 사례에 써도 되는지 스스로 결정한다.

**S10. 화면 시연** — 참관자가 브라우저에서 지표를 입력하거나 예시 경기를 선택하면, 승률·근거·경고가 한 화면에 표시된다.

**S11. 서빙 파리티 확인** — 검토자가 파리티 검증을 실행하면, 웹 계층과 `predict.py` 가 동일 입력에 대해 동일 확률을 냈음을 확인한다.

**S12. 경기 유형 확인** — 사용자가 한 경기가 어떤 유형에 속하는지와, 그 유형에서 10분 리드팀이 최종 승리한 비율을 확인한다.

### Edge Cases

| # | 상황 | 요구되는 처리 |
|---|---|---|
| E1 | 입력에 필수 지표가 빠져 있음 | 예측을 수행하지 않고 누락 항목을 명시해 거부 |
| E2 | 입력 값이 학습 데이터의 관측 범위를 벗어남 | 예측은 반환하되 "학습 범위 밖" 경고를 함께 표시 (001-E4) |
| E3 | 입력이 접전 구간(격차 소구간)에 해당 | 해당 구간의 실측 정확도를 함께 고지 (001-E3) |
| E4 | 파생·중복 지표가 입력에 포함됨 | 학습·예측 양쪽에서 동일 규칙으로 자동 제거 (001-E7) |
| E5 | 예측 시점 이후 정보가 입력에 포함됨 | 입력 명세에 존재하지 않아 구조적으로 수용 불가 (001-E1) |
| E6 | 저장 시점과 다른 지표 순서·이름으로 입력이 들어옴 | 입력 명세와 대조해 불일치를 오류로 거부 |
| E7 | 노트북이 이전 실행에만 존재하던 변수·설치물에 의존해 클린 환경에서 실패 | 각 단계가 앞 단계의 산출만 참조하도록 구성. 필요 준비물은 노트북 첫 단계에 명시 |
| E8 | 데이터 접근 정보가 노트북·서버 코드에 하드코딩되어 재실행·공개가 불가 | 접속 정보는 환경 변수로 주입하고 저장소에는 담지 않는다 |
| E9 | 전처리가 빠진 채 추정기만 저장되어, 복원 후 정규화되지 않은 입력에 다른 예측이 나옴 | 저장 검증(FR-008)이 원본 형태 입력으로 대조해 불일치를 잡아내고 저장을 실패시킨다 |
| **E10** | 학습이 모델을 갱신했는데 웹 계층이 옛 파라미터를 들고 있어 화면 확률이 어긋남 | 파리티 검증(FR-019)이 불일치를 잡아내고 **배포를 실패로 처리**한다. 파라미터는 학습 산출물에서만 생성한다 |
| **E11** | 웹 계층이 편의를 위해 확률을 반올림·보정하거나 규칙을 덧붙여 예측이 갈라짐 | 금지(NFR-008). 표시용 서식은 허용하되 **판단에 쓰이는 값은 변형 불가**, 파리티 검증이 원시 확률로 대조한다 |
| **E12** | 웹 서비스가 내려가 있음 | 예측의 단일 진실은 `predict.py` 이므로 **핵심 기능은 영향받지 않는다**. 웹은 시연 계층이다 |

### Acceptance Scenarios

**AS1 — 예측 반환**
- **Given** 유효한 10분 스냅샷이 주어졌을 때
- **When** `predict(payload)` 를 호출하면
- **Then** 응답 계약(A9)의 다섯 항목을 모두 갖춘 사전이 반환된다

**AS2 — 근거 동봉**
- **Given** 예측 요청이 성공했을 때
- **When** 응답을 확인하면
- **Then** 상위 기여 지표가 방향(+/−)과 크기 순위와 함께 5개 이상 포함되어 있다

**AS3 — 경고와 거부의 구분**
- **Given** `schema.json` 의 허용범위를 벗어난 값, 또는 접전 구간 입력이 주어졌을 때
- **When** 예측을 요청하면
- **Then** 예측은 정상 반환되고 사유를 지목한 **경고**가 함께 나온다
- **And** 반대로 컬럼 누락·이름 불일치·자료형 불일치는 경고가 아니라 **거부**로 처리된다

**AS4 — 누수·중복 차단**
- **Given** 학습에 사용된 지표 목록을 확인할 때
- **When** 목록을 검사하면
- **Then** 예측 시점 이후 항목이 0건이고, 사전 검증된 중복 지표가 모두 제외되어 있다

**AS5 — 저장·복원 일치**
- **Given** `model.joblib` 을 학습 코드가 없는 새 환경에서 복원했을 때
- **When** **가공하지 않은 원본 형태의 입력**으로 곧바로 예측하면
- **Then** 별도 전처리 없이 예측이 수행되고, 저장 이전 예측 확률과 완전히 일치한다

**AS6 — 기준선 병기**
- **Given** 성능 리포트를 조회할 때
- **When** 정확도를 확인하면
- **Then** 무학습 기준선 대비 개선 폭(%p)과 교차검증 평균±표준편차가 함께 표기되어 있다

**AS7 — 요인 교차 검증**
- **Given** 두 가지 독립적인 해석 방법으로 산출한 요인 순위를 대조할 때
- **When** 상위 목록을 비교하면
- **Then** 공통 요인이 5개 이상이며, 공통 요인만 최종 근거로 노출된다

**AS8 — 시점 교체 가능성**
- **Given** 시점 인자를 15분으로 지정했을 때
- **When** 학습·평가 절차를 실행하면
- **Then** 예측 로직 수정 없이 절차가 진행되며, 데이터 미확보 시 명확한 사유와 함께 중단된다

**AS9 — README 단독 인수인계**
- **Given** 프로젝트를 처음 접하는 제3자에게 저장소만 전달했을 때
- **When** `README.md` 만 읽고 실행 방법을 따라가면
- **Then** 추가 질문 없이 학습과 예측을 완주하고, 결과의 한계까지 파악할 수 있다

**AS10 — 노트북 클린 런타임 재실행**
- **Given** 이전 실행 상태가 모두 초기화된 환경에서
- **When** 최종 노트북의 모든 단계를 처음부터 순서대로 실행하면
- **Then** 오류 없이 마지막 단계까지 완주하며, 문서에 기재된 것과 동일한 성능 수치를 산출한다

**AS11 — 모델 카드 단독 판단**
- **Given** 모델을 넘겨받은 제3자가 `model_card.md` 만 읽었을 때
- **When** 자신의 사용 사례가 적절한지 판단하면
- **Then** 용도·성능·금지 상황·한계 네 가지를 근거로 사용 여부를 스스로 결정할 수 있다
- **And** 성능 수치와 함께 접전 구간의 취약성을 반드시 인지하게 된다

**AS12 — 화면 시연**
- **Given** 웹 서비스가 실행 중이고 참관자가 브라우저를 열었을 때
- **When** 예시 경기를 선택하거나 지표를 입력해 예측을 요청하면
- **Then** 승리 확률·근거 지표(방향과 크기)·경고가 **한 화면에** 표시된다
- **And** 근거로 표시되는 지표는 `predict.py` 가 반환한 것과 동일한 목록·순서다

**AS13 — 서빙 파리티**
- **Given** 학습으로 산출된 모델 파라미터를 웹 계층이 적재한 상태에서
- **When** 홀드아웃 전량을 두 경로(`predict.py` / 웹 계층)에 동일 입력으로 통과시키면
- **Then** 두 경로의 승리 확률이 **허용 오차 1e-9 이내로 전건 일치**한다
- **And** 한 건이라도 벗어나면 검증은 실패로 처리되고 배포가 중단된다

**AS14 — 경기 유형 프로파일**
- **Given** 경기 유형 분류 결과를 조회할 때
- **When** 유형별 집계를 확인하면
- **Then** 각 유형의 경기 수와 **10분 리드팀의 최종 승률**이 함께 제시된다
- **And** 분류에 쓰인 지표에 진영(블루/레드) 식별 정보가 포함되지 않는다

### 001에서 넘어온 미결

> 개정 이전에는 001이 15분 비교를 필수로, 002가 후속 이관으로 기술해 서로 모순이었다.
