# Spec — LoL 승패 예측·설명 서비스

> spec-kit 형식의 요구사항 명세. 팀 서버 정본(`specs/002-ml-prediction-service/spec.md` v1.2)을
> 로컬에 정리한 것으로, 어긋나면 정본이 우선한다.
> 구현 계획은 [plan.md](plan.md), 배경·판정 근거는 [planning.md](planning.md).

## 1. 개요

10분 시점의 경기 상태(블루−레드 차이 피처 13개)를 입력받아
① 승리 확률 ② 예측 클래스 ③ 승리요인(방향·크기) ④ 신뢰 가능 여부를 반환하는 서비스.
문제 유형은 지도학습 이진분류(무승부 없음), 1순위 지표는 정확도(승패 50.1:49.9 실측 균형).

## 2. 사용자 시나리오

| 사용자 | 시나리오 | 필요한 것 |
|---|---|---|
| 관전 입문자 | 중계를 보며 "어느 팀이 왜 유리한지" 알고 싶다 | 승률 + 승리요인 순위 + 쉬운 용어 |
| 복기하는 유저 | 진 경기에서 무엇부터 고칠지 우선순위를 원한다 | 요인별 기여도 + 접전 경고 |
| 팀원(개발자) | 모델을 이어받아 재현·확장하고 싶다 | 산출물 6종 + 재현성 규약 |

## 3. 기능 요구사항 — v1 (전부 구현 완료)

| ID | 요구사항 | 상태 |
|---|---|---|
| FR-1 | 경기 상태 입력 → 승리 확률(%) + 예측 클래스 (`predict(payload)→dict`) | ✅ predict.py 스모크 3건 통과 |
| FR-2 | 승리요인을 방향(+/−)과 크기로 제시 — 계수 × permutation 교차 확인 | ✅ 유의 요인 3개 순위 일치 |
| FR-3 | 승리요인을 "관전 시 주목할 지표 목록"으로 정리 | ✅ README 부록 |
| FR-4 | 오류 패턴 리포트 — "접전일수록 틀린다"를 구간별 정확도로 검증 | ✅ 접전 0.615 vs 결정 0.947 |
| FR-5 | 경기 유형 프로파일 (사이드 중립 KMeans, 유형별 리드팀 승률) | ✅ 4유형 |
| FR-6 | 관측 시점을 인자로 받는 구조 (`TIME_POINT`) | ✅ |
| FR-7 | 10분 vs 15분 통제 비교 (같은 경기·피처·분할) | ✅ +5.25%p, 접전만 +7.8%p |
| FR-8 | 기준선(찍기 0.50) 대비 개선 폭 병기 | ✅ +23.8%p |
| FR-9 | 웹 데모 — 입력 폼 → 승률 + 승리요인 표시 | ✅ Flask, 파리티 3건 일치 |

## 4. 품질 요구사항 (비기능)

- **ML 전용 구현** — 모든 예측·해석은 학습된 Pipeline에서만. 규칙 하드코딩·확률 수동 보정·외부 승률 API 금지
- **누수 원천 차단** — 분할이 전처리보다 먼저 · 예측 시점 이후 정보 입력 금지 · 전처리는 Pipeline 내부
- **재현성 규약 8항목** — 시드 42 · 분할 파일 저장 · 절대경로 금지 · 버전 고정 · 순차 실행 · Pipeline 내부 전처리 · runs.csv 기록 · 행 정렬 고정(gameId)
- **서빙 파리티** — 웹의 확률은 predict.py와 동일 입력에서 일치함을 자동 테스트로 검증
- **아티팩트 검증** — joblib 저장→복원→예측 일치 assert · 클린 런타임 무오류

| ID | 기준 | 판정 |

| SC-2 | 안정성 (5-fold std < 0.02, 학습−검증 격차 < 0.03) | ✅ 0.0153 / +0.0022 |

| SC-4 | "이런 경기에서 틀린다"를 수치로 제시 | ✅ 골드차 구간별 0.615→0.947 |
| SC-5 | 산출물 6종 + 복원 assert 통과 | ✅ 6/6 |

### SC-7 실행 기록 (2026-09-01 · 게임 안 하는 1명)

관전 포인트 3줄만 보여주고 세 가지를 물었습니다.

| 질문 | 답변 | 판정 |
|---|---|---|
| 파란 팀이 돈 4,500 앞섬 | "돈 많으니 파란 팀" | ✅ 답과 이유를 함께 말함 |
| 돈 차이가 400 | "비슷해서 모르겠다" | ✅ 접전의 한계를 이해 |
| 킬 5개 앞섰지만 돈 차이 200 | "킬 많으니 파란 팀" | ❌ **오답** |

**발견** — 세 번째에서 갈렸습니다. 관전 포인트에 **킬 이야기가 아예 없어서**,
"킬이 많으면 유리하다"는 상식대로 답한 것입니다. 우리 분석의 핵심 결론
(킬은 돈으로 환산됐을 때만 의미가 있다)이 관전 가이드에 빠져 있었습니다.

**조치** — README 부록에 킬 항목을 추가했습니다.
"킬을 많이 했어도 돈 차이가 안 벌어졌다면 아직 유리한 게 아니다."

**남은 한계** — 표본 1명이고, 보완한 문구로 다시 테스트하지는 못했습니다.
다만 **테스트가 실제로 문서의 구멍을 찾아냈다는 것** 자체가 이 항목의 목적이었습니다.

## 7. 후속 아이디어 — "시점 조건부 승률 곡선" (미확정)

> ⚠️ **확정 요구사항이 아니다.** 프로젝트는 4일 완주(1~6장)로 끝났고 후속 개발 여부는 미정이다.
> 만약 이어서 한다면, 한계 — 10분·15분 두 점만 비교, 접전(33%)은 동전던지기, 랭크 일반화 미검증 —
> 를 이렇게 풀면 좋겠다는 제안이다. 구상은 [plan.md](plan.md) 7장.

| ID | 요구사항 | 수용 조건 |
|---|---|---|
| FR-10 | **분 단위 시점 조건부 예측** — 경과 시간 t(5~25분)를 입력받아 그 시점 정보만으로 승률 반환 | 시점–성능 곡선 산출(5분 간격 이상), FR-6 구조 재사용 |
| FR-11 | **보정된 확률** — 출력 확률이 실제 승률과 일치 (승률 70%로 예측한 경기들의 실제 승률 ≈ 70%) | calibration curve + Brier, 접전 구간 별도 보고 |
| FR-12 | **통제된 검증** — 같은 팀/소환사가 학습·시험 양쪽에 못 들어가게, 패치 경계로 시간순 분할 | GroupKFold(팀 단위) + 시간순 홀드아웃 병행 |
| FR-13 | **시점별 승리요인 변화 리포트** — t에 따라 요인 순위가 어떻게 바뀌는지 (실험 B ② 의 일반화) | 시점별 계수·중요도 표, 해석 가능성 유지 |

한다면 성공 기준은: 시점–성능 곡선이 단조 증가하고 각 시점에서 기준선을 상회할 것 ·
접전 구간 정확도가 개선되거나 불가능함이 통제 실험으로 입증될 것 ·
보정 오차(Brier)가 현재(0.1756) 이하이고 팀 그룹 분할에서도 안정성 기준(SC-2)이 유지될 것.
