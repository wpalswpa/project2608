## 2. 반드시 알아야 할 결정 사항

**서비스 이름은 `LOL.EX`** (op.gg 형식). 단 **README 제목은 건드리지 않는다** —
`# LoL 경기는 언제 승부가 결정되는가?` 가 DDBM 에 등록된 제목이다.
이름은 **서비스 화면에만** 쓴다.

**최종 모델은 13개 피처(골드 포함)를 쓴다.** 페이즈 2 에서 골드를 뺀 것은
"킬 계수가 왜 음수인가"를 밝히려던 **진단이지 채택이 아니다.**
페이즈 3 도 골드를 포함한 채로 비교했다.

**1차 고객은 개인이 아니라 중계 사업자·스트리머다.** 파는 것은 승률 숫자가 아니라
캐스터가 읽을 **"할 말"** 이다. 베팅·배당은 불가, 방송사의 무료 승부예측 이벤트
분석 근거 제공은 가능 — 이 선을 넘지 않는다.

**화면에 숫자를 하드코딩하지 않는다.** 구간별 적중률·경계값은 전부 서버가
`/api/report` 로 내려준다. 경계 정본은 `lolwin/features.py` 의 `GOLD_BINS`.

## 4. 지금 남은 일

### ① 서비스 화면 랜딩형 재구성 (ml-7d 담당, 미완)

현재 화면은 "13개 숫자를 입력하세요" 폼이 첫 화면이다. 이건 분석가용이지 상품이 아니다.
아무도 골드차를 손으로 타이핑하지 않는다.

바꿀 방향:

| 지금 | 바꿀 것 |
|---|---|
| 13개 입력 폼이 첫 화면 | **중계 오버레이 미리보기**가 첫 화면 |
| "예측하기" 버튼 | 경기 상황 **프리셋 클릭 → 즉시 반응** |
| 성적표·요인 표를 한 번에 | **캐스터 멘트 한 줄** + 근거는 접어서 |
| 보고서 톤 | 제품 랜딩 — 문제 → 데모 → 근거 → 도입 방법 |

13개 폼은 없애지 않고 "고급/직접 입력"으로 접어 내린다(발표에서 근거를 보여줘야 한다).

**지키면서 바꿀 것** — 13개 피처 ID·순서, API 5종(`/api/predict` `/api/schema`
`/api/report` `/api/match-types` `/api/summoner`), Jinja 변수(`domain`
`backend_ok` `riot_ready`), 데모 3종 값. `web/frontend.py`·`app.py` 는 안 건드려도 된다.
