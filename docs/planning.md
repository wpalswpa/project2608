> **발표 주제**: LoL 경기는 언제 승부가 결정되는가? — 인게임 시점별 경기 데이터 기반 승패 예측 및 핵심 승리요인 분석
> **시스템 이름**: LoL 승패 예측·설명 서비스 (10분 데이터로 승률과 '왜'까지)

## 문제 영역 (PROBLEM DOMAIN)

1. **관전의 "왜"가 비어 있다** — 중계에 승률 지표가 도입됐지만 산출 근거가 비공개라,
   시청자는 "지금 63%"를 봐도 왜 유리한지 모른다. → 설명 가능한 승률을 만든다.
2. **분석의 접근성 격차** — 프로팀은 전담 분석 인력이 있지만 일반 유저는 없다.
   → 공개 데이터와 기본 ML만으로 복기 우선순위를 뽑는 절차를 보인다.
3. **통제되지 않은 시점 비교** — 10분 예측 분석은 많지만(70~75% 보고),
   "몇 분을 더 보면 얼마나 정확해지나"를 같은 경기·같은 피처로 통제한 비교는 드물다.

## 지식 기반 (KNOWLEDGE BASE)

- **방법론**: CRISP-DM · 수업의 5단계 13항목 파이프라인
- **이론**: 이진분류, 분할·누수 방지, 교차검증, 혼동행렬, 임계값,
  계수·permutation 해석, 표본 선택 편향, PCA·KMeans·실루엣
- **선행 사례**: 동일 데이터 공개 분석 다수 (70~75%) — 우리 결과의 타당성 기준
- **도메인**: 10분 = 라인전이 끝나는 체크포인트 · 골드→장비→교전의 스노우볼 구조 ·
  무승부 없음(이진분류 성립) · 결론은 수집 시점 패치에 한정
- **도구·데이터**: Python · scikit-learn Pipeline · joblib · 팀 MariaDB(비밀번호는 환경변수) ·
  Kaggle 다이아 10분 스냅샷(메인) · Oracle's Elixir 프로 경기(시점 비교)

## 설계 인공물 (DESIGN ARTIFACT)

**핵심 — "시점 조건부 승패 예측 파이프라인"**: 특정 시점까지의 정보만 받아
승리 확률과 승리요인을 함께 반환. 시점(10분/15분)만 바꿔 재학습 가능.

산출하는 것: ① 시점 승률 ② 10 vs 15분 비교표 ③ 승리요인 순위표
④ 오류 패턴 리포트 ⑤ 경기 유형 프로파일.
감싸는 것: 산출물 6종(README·노트북·model.joblib·schema.json·predict.py·model_card) + 웹 데모.

## 설계 요구사항 (DESIGN REQUIREMENTS)

- **기능**: 승률+예측 클래스 반환 · 승리요인 방향·크기 제시 · 관전 지표 목록 ·
  10/15분 동일 기준 비교 · 기준선 대비 개선 폭 병기 · 웹 데모(입력 폼 → 승률+요인)
- **품질**: ML 전용 구현(규칙 하드코딩·확률 보정·외부 API 금지) · 누수 원천 차단 ·
  시점 비교 표본 통제 · 해석가능성 · 재현성 규약 · 복원 assert · 서빙 파리티 · 1코어·4일 완주
- 항목별 전체 목록과 판정은 [spec.md](spec.md)

## 설계 원리 (DESIGN PRINCIPLES)

1. **기준선 우선** — 모든 성능 주장은 찍기 점수와의 비교로 시작
2. **누수 불가능 설계** — 예측 시점을 먼저 고정해 이후 정보를 구조적으로 배제
3. **비교는 통제된 조건에서만** — 바꾸려는 변수(시점) 하나만 바꾼다
4. **해석 가능성 > 점수** — 점수가 비슷하면 설명되는 모델이 맞다
5. **검증된 점수만 보고** — 평균±표준편차로 "운이 아님"을 증명한 뒤에만
6. **이어받을 수 있게** — 재현·운영·확장 가능한 절차로 남긴다
7. **모델이 말하게 한다** — 게임 지식은 피처 설계와 검증에만 쓰고, 예측 규칙으로 넣지 않는다

## 개발 방법 (DEVELOPMENT METHOD)

Day1 문제번역·EDA·분할·베이스라인 → Day2 전처리·차이 피처·군집 →
Day3 모델 비교·교차검증·임계값 → Day4 시점 비교·해석·오류 분석·아티팩트·문서.
막힐 때 순서: **모델 교체 → 특성 공학 → 튜닝** (튜닝 먼저는 금지).

## 평가 방법·기준 (EVALUATION)

- 실험 A(다이아)와 B(프로)를 분리하고 절대 수치를 섞지 않는다
- 홀드아웃 + 5-fold 층화 교차검증, 학습·검증 점수 병기, 찍기 대비 개선 폭 병기
- 1순위 지표 **정확도** (균형 실측 + 비용 대칭 — 치우쳤다면 F1로 전환할 계획이었음)
- 개선도: 하한 0.70 (미달 시 파이프라인 점검) / 목표 0.75 (도전)
- 안정성: 폴드 std < 0.02 · 학습−검증 격차 < 0.03
- 해석: 상위 요인이 계수·permutation 두 방법에서 일치할 것
- 판정 결과는 [spec.md](spec.md) 5장 (SC-1~6 통과, SC-7 부분 통과 — 오답을 근거로 부록 보완)
